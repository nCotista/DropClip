## 1. ภาพรวมระบบแบบเข้าใจง่าย (What is DropClip?)

**DropClip** คือโปรแกรมสำหรับส่งข้อความที่กดคัดลอก (Copy/Paste) และส่งไฟล์ขนาดใหญ่ข้ามเครื่องคอมพิวเตอร์ (macOS, Windows) และมือถือ (Android, iOS) ที่อยู่ในวง Wi-Fi เดียวกัน:
- **ไม่ต้องใช้อินเทอร์เน็ต ไม่ต้องใช้ Cloud และไม่ต้องสมัครสมาชิก** (ข้อมูลวิ่งตรงระหว่างเครื่องต่อเครื่อง 100%)
- **ปลอดภัยด้วยมาตรฐาน TLS 1.3** และการยืนยันรหัส 6 หลัก (**SAS Code**) โดยไม่ส่งรหัส PIN ผ่านเครือข่ายเลย (**Zero-PIN-on-Wire**)
- **ไม่กินแรม (RAM)** แม้ส่งไฟล์ขนาดใหญ่หลายกิกะไบต์ เพราะแบ่งส่งทีละ `1 MiB` และส่งต่อจากจุดเดิมได้หาก Wi-Fi หลุดกลางคัน

## 2. สิ่งที่ต้องเตรียมก่อนเริ่ม (Pre-Flight Setup)

หากเครื่องคอมพิวเตอร์ที่นำมาใช้ทดสอบติดตั้ง **Flutter** ไว้แล้ว สามารถทำตามขั้นตอนนี้ได้ทันที (คัดลอกคำสั่งไปวางในโปรแกรม **Terminal** บน Mac หรือ **PowerShell** บน Windows):

### ขั้นตอนที่ 2.1: เปิดโปรแกรมสั่งงาน (Terminal / PowerShell)
- **บน macOS:** กดปุ่ม `⌘ Command + Space` พิมพ์คำว่า `Terminal` แล้วกด `Enter`
- **บน Windows:** กดปุ่ม `Windows` พิมพ์คำว่า `PowerShell` แล้วกด `Enter`

### ขั้นตอนที่ 2.2: เข้าไปยังโฟลเดอร์โปรเจกต์และเตรียมความพร้อม (ทำครั้งเดียว)
คัดลอกคำสั่งด้านล่างไปวางในหน้าต่าง Terminal แล้วกด `Enter`:

```bash
cd /path/to/DropClip
melos bootstrap
```
*(หมายเหตุ: เปลี่ยน `/path/to/DropClip` เป็นตำแหน่งโฟลเดอร์จริงบนเครื่อง เช่น `cd ~/Documents/github/DropClip` หากเครื่องยังไม่มีคำสั่ง `melos` สามารถรัน `dart pub global activate melos` ก่อนได้)*

## 3. วิธีเปิดโปรแกรม Desktop และ Mobile (How to Launch)

คุณสามารถเปิดทดสอบได้ทั้งบนเครื่องคอมพิวเตอร์เดียว (เปิดหน้าต่าง Desktop คู่กับหน้าต่างจำลอง Mobile) หรือเปิดข้ามเครื่องจริงในวง Wi-Fi เดียวกัน

### 3.1 วิธีเปิดแอปฝั่งคอมพิวเตอร์ (Desktop App — macOS / Windows)
ในหน้าต่าง Terminal พิมพ์คำสั่ง:

**สำหรับเครื่อง Mac (macOS):**
```bash
cd apps/desktop
flutter run -d macos
```

**สำหรับเครื่อง Windows:**
```bash
cd apps/desktop
flutter run -d windows
```

เมื่อหน้าต่างโปรแกรม **DropClip Desktop** เด้งขึ้นมา คุณจะเห็นแถบเมนูด้านซ้าย 4 หมวดหมู่:
1. **Clipboard (คลิปบอร์ด):** หน้าหลักสำหรับดูประวัติข้อความ/ลิงก์/รูปภาพที่คัดลอก และรายชื่ออุปกรณ์ใกล้เคียงทางขวา
2. **Transfers (การส่งไฟล์):** หน้าแสดงรายการไฟล์ที่กำลังส่ง/รับ พร้อมแถบความคืบหน้า (Progress Bar)
3. **Devices (อุปกรณ์):** หน้าจับคู่อุปกรณ์ด้วยรหัส PIN 6 หลัก และจัดการอุปกรณ์ที่เชื่อถือ
4. **Settings (การตั้งค่า):** หน้าเปลี่ยนภาษา (English / ไทย), ตั้งค่าการเปิดอัตโนมัติ และเวลาลบคลิปบอร์ดอัตโนมัติ (TTL)

---

### 3.2 วิธีเปิดแอปฝั่งมือถือ (Mobile App — Android / iOS หรือจำลองบนคอมพิวเตอร์)
เปิดหน้าต่าง Terminal **อีกใบหนึ่ง** แล้วพิมพ์คำสั่ง:

```bash
cd apps/mobile
flutter run
```
- หากเสียบสายมือถือ Android หรือเปิด iOS Simulator / Android Emulator ไว้ แอป **DropClip Mobile** จะเปิดขึ้นบนหน้าจอมือถือทันที
- **พิเศษสำหรับผู้ที่มีคอมพิวเตอร์เครื่องเดียวและไม่มีมือถือต่ออยู่:** คุณสามารถรัน `flutter run -d macos` (หรือ `-d windows`) ในโฟลเดอร์ `apps/mobile` เพื่อเปิดหน้าจอแอปมือถือเป็นหน้าต่างที่สองบนคอมพิวเตอร์เครื่องเดียวกันเพื่อกดทดสอบคู่กันได้เลย!

## 4. 7 สถานการณ์ทดสอบจริงทีละขั้นตอน (7 Step-by-Step Test Scenarios)

ผู้ทดสอบสามารถกดตาม 7 ขั้นตอนด้านล่างนี้ตามลำดับ เพื่อพิสูจน์ว่าทุกฟีเจอร์ของโปรเจกต์ทำงานได้จริงครบถ้วน:

---

### การทดสอบที่ 1: จับคู่อุปกรณ์ด้วยรหัส PIN 6 หลัก และตรวจรหัสความปลอดภัย SAS (Pairing & Security)
**เป้าหมาย:** พิสูจน์ว่าการจับคู่อุปกรณ์คำนวณรหัสยืนยันตัวตน (SAS 6 หลัก) ตรงกันทั้งสองฝั่งโดยไม่ต้องส่ง PIN ผ่านเครือข่าย (`T1.3`, `ADR-009`)

1. **ที่หน้าต่าง Desktop:**
   - คลิกเมนู **`Devices` (อุปกรณ์)** ที่แถบด้านซ้าย (หรือคลิกปุ่ม **`Pair new device`** ทางด้านขวาของหน้า Clipboard)
   - สังเกตกล่อง **"Zero-PIN-on-Wire Pairing Host"**:
     - ช่อง **6-Digit OOB PIN** จะแสดงค่าเริ่มต้นคือ `123456`
     - กล่องรหัสยืนยันจะแสดง **`SAS: 639589`**
2. **ที่หน้าต่าง Mobile:**
   - แตะแท็บ **`Devices`** ด้านล่างสุด
   - ในกล่อง **"Pair New Device (Zero-PIN-on-Wire)"** สังเกตช่อง **6-Digit Manual PIN** ที่มีค่า `123456`
   - แตะปุ่ม **`Pair & Compute SAS`**
3. **ผลลัพธ์ที่ต้องเห็น (Expected Result):**
   - หน้าจอ Mobile จะแสดงข้อความ **`Computed SAS Code: 639589`** ซึ่งตรงกับหน้าจอ Desktop (`SAS: 639589`) ทุกตัวอักษร!
   - ลองเปลี่ยนเลข PIN ในช่องเป็นเลข 6 หลักอื่น (เช่น `654321`) ทั้งสองฝั่ง รหัส SAS ทั้งสองฝั่งจะเปลี่ยนเป็นเลขชุดใหม่ที่ตรงกันทันที
   - คลิกปุ่ม **`Confirm SAS Match`** บน Desktop — จะขึ้นข้อความสีเขียว *"Peer pinned in Trusted Peer Store (TLS 1.3 SPKI SHA-256)"*

---

### การทดสอบที่ 2: คัดลอกและส่งข้อความ/ลิงก์ข้ามเครื่อง (Clipboard Continuity)
**เป้าหมาย:** พิสูจน์ว่าสามารถส่งข้อความที่คัดลอกเข้าสู่คลัสเตอร์ ค้นหา กรองตามประเภท และกดคัดลอกซ้ำได้ (`T1.9`, `T2.2`, `T2.3`)

1. **ที่หน้าต่าง Desktop (หน้า `Clipboard`):**
   - ลองคัดลอกข้อความใดก็ได้บนคอมพิวเตอร์ (กด `⌘+C` หรือ `Ctrl+C`) แล้วคลิกปุ่มสีน้ำเงิน **`Send clipboard` (ส่งคลิปบอร์ด)** ด้านบน
   - **ผลลัพธ์:** ข้อความที่คุณคัดลอกจะปรากฏขึ้นเป็นรายการแรกสุดในหมวด **RECENT** ทันที!
   - ลองคลิกปุ่มตัวกรอง **`Links`** หรือ **`Text`** หรือพิมพ์ค้นหาในช่อง **`Search recent clips…`** (เช่น พิมพ์คำว่า `github`) — รายการจะกรองเฉพาะที่ตรงคำค้นหาทันที
   - คลิกไอคอน **Copy (รูปกระดาษซ้อนกัน)** ท้ายรายการใดก็ได้ — จะมีแถบแจ้งเตือนด้านล่างขึ้นว่า **`Copied to clipboard`**
2. **ที่หน้าต่าง Mobile:**
   - ในแท็บ **`Devices`** ลองแตะปุ่ม **`QS Tile: Send Clipboard`** (จำลองการกดปุ่มลัดจากแผงแจ้งเตือนด้านบนของ Android — `T2.2`)
   - สลับไปที่แท็บ **`Clipboard`** ด้านล่าง:
     - พิมพ์ข้อความในช่อง (เช่น `"Hello from Mobile!"`) แล้วแตะปุ่ม **`Send to Cluster`**
     - แตะปุ่ม **`Simulate Inbound Clip`** (จำลองการรับคลิปบอร์ดที่ส่งมาจากเครื่องคอมพิวเตอร์ — `T2.3`)
3. **ผลลัพธ์ที่ต้องเห็น (Expected Result):**
   - รายการคลิปบอร์ดจะเพิ่มเข้าสู่หน้าประวัติทันที พร้อมแถบแจ้งเตือนด้านล่างยืนยันการซิงก์และแสดงความหน่วง (Sync Latency) ต่ำกว่าเป้า `< 1,000 ms`

---

### การทดสอบที่ 3: ทดสอบระบบป้องกันรหัสผ่านรั่วไหล (Password Manager Suppression)
**เป้าหมาย:** พิสูจน์ว่าข้อมูลรหัสผ่านจากโปรแกรมประเภท 1Password / Bitwarden / Keychain จะถูกบล็อก 100% และไม่ถูกส่งออกนอกเครื่องเด็ดขาด (`NFR-S04`, `T1.6`–`T1.8`)

1. **ที่หน้าต่าง Desktop (หน้า `Clipboard`):**
   - เลื่อนลงมาด้านล่างสุดของรายการคลิปบอร์ด
   - **ผลลัพธ์:** จะเห็นกล่องแจ้งเตือนรูปแม่กุญแจสีเขียวระบุว่า *"1 item from a password manager not synced — password-manager content never leaves this device"* (นับเฉพาะจำนวนที่บล็อกไว้ โดยไม่แสดงรหัสผ่านบนหน้าจอ)
2. **ที่หน้าต่าง Mobile (แท็บ `Clipboard`):**
   - เปิดสวิตช์ **`Mark as Sensitive (Password Manager / Concealed)`** ให้เป็นสีน้ำเงิน (ON)
   - พิมพ์รหัสผ่านสมมติลงในช่อง แล้วแตะปุ่ม **`Send to Cluster`**
3. **ผลลัพธ์ที่ต้องเห็น (Expected Result):**
   - ระบบจะ **ปฏิเสธการส่งทันที** และแสดงแถบเตือนสีแดงด้านบนว่า:
     **`Suppressed sensitive clipboard item (NFR-S04)`**
   - รหัสผ่านดังกล่าวจะไม่ปรากฏในประวัติการส่ง และไม่ถูกส่งออกไปที่เครือข่าย

---

### การทดสอบที่ 4: ลากไฟล์ส่งผ่าน Dropzone แบบความเร็วสูง (Streaming File Transfer)
**เป้าหมาย:** พิสูจน์การทำงานของหน้าต่างลอย Dropzone และการส่งไฟล์แบบแบ่งส่วน 1 MiB พร้อมตรวจ SHA-256 (`T1.10`, `UI-02`)

1. **ที่หน้าต่าง Desktop:**
   - กดคีย์ลัด **`⌥ Option + ⌘ Command + D`** (บน Mac) หรือ **`Ctrl + Alt + D`** (บน Windows) หรือคลิกการ์ด **`Drop files to send`** ทางด้านขวาของหน้าจอ
   - หน้าต่างลอย **Dropzone** จะเด้งขึ้นมากลางหน้าจอ
2. **การส่งไฟล์:**
   - ลากไฟล์หรือโฟลเดอร์ใดก็ได้จากเครื่องของคุณมาวางในกรอบสีน้ำเงินของ Dropzone (ใช้ปุ่มลูกศร `↑`/`↓` เลือกอุปกรณ์ปลายทาง แล้วกด `Enter` หรือคลิกปุ่ม **`Send to ...`**)
   - หรืออีกวิธีหนึ่ง: คลิกเมนู **`Transfers` (การส่งไฟล์)** ทางด้านซ้าย แล้วคลิกปุ่ม **`Stream Sample File (1 MiB Chunks)`**
3. **ผลลัพธ์ที่ต้องเห็น (Expected Result):**
   - หน้าจอจะสลับมายังหน้า **`Transfers`** และแสดงรายการไฟล์ที่ส่งเสร็จสมบูรณ์ **`100% · SHA-256 Verified`**

### การทดสอบที่ 5: ส่งไฟล์ต่อจากจุดที่ค้างเมื่อเน็ตหลุด (Resumable `.part` Transfer)
**เป้าหมาย:** พิสูจน์ว่าหากส่งไฟล์ขนาดใหญ่แล้ว Wi-Fi หลุดกลางคัน ระบบสามารถส่งต่อจากจุดที่ค้างไว้ (`.part`) ได้โดยไม่ต้องเริ่มนับศูนย์ใหม่ (`T1.11`)

1. **ที่หน้าต่าง Desktop:**
   - คลิกเมนู **`Transfers` (การส่งไฟล์)** ทางแถบด้านซ้าย
   - สังเกตรายการไฟล์ **`4K-Demo-Recording.mp4.part`** ที่ค้างอยู่ที่ **`50% · Paused (.part)`**
   - คลิกปุ่ม **`Resume .part (T1.11)`** ที่อยู่มุมขวาของรายการนั้น
2. **ที่หน้าต่าง Mobile:**
   - แตะแท็บ **`Transfers`** ด้านล่างสุด
   - สังเกตรายการ **`movie_4k_uhd.mp4.part`** ที่ค้างอยู่ที่ 50%
   - แตะปุ่ม **`Resume Interrupted .part`**
3. **ผลลัพธ์ที่ต้องเห็น (Expected Result):**
   - แถบความคืบหน้าจะวิ่งต่อจาก **50% ไปจนครบ 100%** ทันที พร้อมเปลี่ยนชื่อไฟล์จาก `.part` เป็นไฟล์จริงที่ตรวจ SHA-256 ผ่านเรียบร้อย!

### การทดสอบที่ 6: ยกเลิกสิทธิ์อุปกรณ์ที่สูญหายอย่างปลอดภัย (Quarantine-then-Confirm Revocation)
**เป้าหมาย:** พิสูจน์ระบบกักกันอุปกรณ์ก่อนเพิกถอนถาวร เพื่อป้องกันกรณีเครื่องที่ถูกขโมยพยายามสั่งลบเครื่องอื่นในกลุ่ม (`T1.12`, `SRS FR-11`)

1. **ที่หน้าต่าง Desktop:**
   - คลิกเมนู **`Devices` (อุปกรณ์)** ทางซ้าย แล้วเลื่อนลงมาที่หัวข้อ **TRUSTED CLUSTER & QUARANTINE-THEN-CONFIRM REVOCATION**
   - ลองคลิกปุ่ม **`Quarantine`** ที่หลังชื่ออุปกรณ์ `Pixel 8` — สถานะจะเปลี่ยนเป็น **`QUARANTINED`** (กักกันชั่วคราว)
   - เมื่ออยู่ในสถานะกักกัน คุณสามารถเลือกกด:
     - **`Confirm Revoke`** เพื่อเพิกถอนสิทธิ์ถาวร (เปลี่ยนเป็น **`REVOKED`**) หรือ
     - **`Restore Peer`** เพื่อคืนสิทธิ์กลับมาเป็น **`TRUSTED`** หากเป็นการเข้าใจผิด
2. **ที่หน้าต่าง Mobile:**
   - ในแท็บ **`Devices`** เลื่อนลงมาที่รายการ **`Lost Tablet`** ซึ่งมีป้ายแจ้งเตือน `QUARANTINED`
   - สามารถกด **`Confirm Revoke`** หรือ **`Reject (Restore)`** ได้เช่นเดียวกัน

### การทดสอบที่ 7: เปลี่ยนภาษา ไทย/อังกฤษ ทันที และเปิดคอนโซลตรวจสอบความปลอดภัย (Settings & Privacy Logs)
**เป้าหมาย:** พิสูจน์การรองรับ 2 ภาษาแบบสลับทันทีโดยไม่ต้องปิดเปิดแอปใหม่ (`NFR-L01`) และการกรองข้อมูลความลับออกจากระบบบันทึก Log (`T0.3`, `NFR-S02`)

1. **การเปลี่ยนภาษา (Thai / English):**
   - ที่หน้าต่าง Desktop คลิกเมนู **`Settings` (การตั้งค่า)** ทางซ้ายสุด
   - ในหัวข้อแรกสุด สลับปุ่มภาษาระหว่าง **`English`** และ **`ไทย`**
   - **ผลลัพธ์:** เมนูและข้อความทุกหน้าจอจะเปลี่ยนเป็นภาษาไทย (หรือภาษาอังกฤษ) ทันทีโดยไม่ต้องรีสตาร์ทโปรแกรม!
2. **การเปิด Debug Console:**
   - กดคีย์ลัด **`⌘ Command + ⇧ Shift + D`** (บน Mac) หรือ **`Ctrl + Shift + D`** (บน Windows)
   - แผง **Debug Console** ด้านล่างจะเปิดขึ้น แสดงบันทึกการทำงานในรูปแบบ JSON ที่ผ่านการกรองข้อมูลส่วนตัวออกทั้งหมด (ไม่มีรหัสผ่านหรือเนื้อหาคลิปบอร์ดปรากฏใน Log แม้แต่บรรทัดเดียว)

## 5. วิธีรันชุดทดสอบอัตโนมัติสำหรับตรวจรับงาน (One-Click Automated Verification)

หากต้องการให้คอมพิวเตอร์รันชุดทดสอบอัตโนมัติทั้งหมดเพื่อยืนยันความถูกต้องของโค้ดทั้งระบบ สามารถรันคำสั่งต่อไปนี้ใน Terminal ได้เลยครับ:

```bash
# 1. รัน Unit & Widget Tests ทั้งหมดในทุกแพ็กเกจและแอป
melos run test

# 2. ตรวจสอบคุณภาพโค้ดและกฎความปลอดภัย (ต้องได้ 0 errors / 0 warnings)
melos run analyze

# 3. รันชุดทดสอบ Native C++ Clipboard Engine (สำหรับ macOS / Linux / Windows)
clang++ -std=c++17 -I native/windows native/windows/clipboard_core_test.cpp -o /tmp/clipboard_core_test && /tmp/clipboard_core_test

# 4. รันชุดทดสอบตัวรับไฟล์ขนาดใหญ่ 4 GiB Streaming Receiver (Python)
python3 tools/s02_receiver/receiver_test.py
```

## 6. การแก้ไขปัญหาเบื้องต้น (Troubleshooting FAQ)

| อาการที่พบ | สาเหตุและวิธีแก้ไขแบบง่าย |
|---|---|
| พิมพ์ `melos` แล้วขึ้นว่า `command not found` | รันคำสั่ง `dart pub global activate melos` แล้วปิด-เปิดหน้าต่าง Terminal ใหม่อีกครั้ง |
| อุปกรณ์ 2 เครื่องมองไม่เห็นกันในรายการ Nearby | ตรวจสอบว่าทั้ง 2 เครื่องเชื่อมต่อ **Wi-Fi ชื่อเดียวกัน** และไม่ได้ใช้ Wi-Fi สาธารณะที่บล็อกการคุยกันระหว่างเครื่อง (Client Isolation) หรือใช้การจับคู่ด้วยรหัส PIN ในหน้า `Devices` ได้ทันที |
| บน Windows มีหน้าต่าง Windows Defender Firewall เด้งถาม | ให้ติ๊กถูกที่ **Private networks (เครือข่ายส่วนตัว)** แล้วกด **Allow access** ตามคำแนะนำบนการ์ดแจ้งเตือนในโปรแกรม |
