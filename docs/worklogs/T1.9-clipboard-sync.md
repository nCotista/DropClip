## 2. Key Decisions
* **ไม่ผูกกับ JSON envelope** (T0.2 ของ `LEAD` ยังไม่มี envelope classes) — engine ใช้ `ClipUpdate` แล้วให้ T0.2 แปลงเป็น `clipboard.update`
* **`noteOwnWrite(hash)`** เป็น public ให้ขารับเรียกก่อนเขียน OS clipboard (§10.3 step 10) และใช้ทดสอบ echo suppression ได้จริง
* **เจอจากการจำลอง (แก้แล้ว):** event ของ watcher ที่มาช้าจากการเขียนของเรา อ่านได้ข้อมูลที่ผู้ใช้เพิ่ง copy ใหม่ → hash ไม่ตรง `_lastAppliedHash` → ส่ง copy นั้นซ้ำ (ได้ 1,631 แทน 1,000); แก้ด้วย `changeToken` ตาม §14.1 — **T1.6/T1.7 ต้องส่ง `changeToken` และอ่านเนื้อหา ณ ตอนที่ event เกิด**
* **ไม่ใช้ `TestCluster` (T0.4)** สำหรับ 1,000 event เพราะใช้เวลาจริงและส่ง Map — ใช้ simulator แบบ deterministic (seed) ใน test แทน
* **เนื้อหาไม่เคยถูกส่งเข้า `log`** (NFR-S02) — log แค่ชื่อ event, ชนิด, ขนาด
