## 1. Objective & Scope
แกนของ T1.9 ตาม Protocol Spec §10 เป็น pure Dart ใน `dropclip_clipboard` — transport (T1.5), blob store (T1.10) และ native watcher (T1.6/T1.7) ยังไม่เสร็จ จึงต่อผ่าน interface `SyncPorts`:
- **PR A1 — `feat/T1.9-sync-types`** (§10.1): data types, `SeenIds`, `History`
- **PR A2 — `feat/T1.9-sync-outbound`** (§10.2)
  - [x] `ClipUpdate`/`ClipEntry`/`SyncPolicy`, `SeenIds` (LRU 200), `History` (Ring 20)
  - [x] ขาออก: ปิดซิงก์/ชนิดไม่อนุญาต → จบ; concealed → ทิ้ง**ก่อน hash** และ log แค่ชนิด (FR-05, NFR-S04); กัน echo ด้วย hash + 800 ms; ≤ 32 KiB inline / ใหญ่กว่าเป็น blob / > 32 MiB ทิ้ง; HLC tick + persist ทุกครั้ง; TTL ล้างเฉพาะเมื่อยังเป็นของเรา
- **PR B — `feat/T1.9-sync-inbound`** (§10.3) ถัดไป: ขารับ 12 ขั้น + ทดสอบ 4 เครื่อง 1,000 event ลู่เข้าค่าเดียวกันไม่วนซ้ำ (NFR-RE02)

## 2. Key Decisions
* **ไม่ผูกกับ JSON envelope** (T0.2 ของ `LEAD` ยังไม่มี envelope classes) — engine ใช้ `ClipUpdate` แล้วให้ T0.2 แปลงเป็น `clipboard.update`
* **`noteOwnWrite(hash)`** เป็น public ให้ขารับเรียกก่อนเขียน OS clipboard (§10.3 step 10) และใช้ทดสอบ echo suppression ได้จริง
* **เนื้อหาไม่เคยถูกส่งเข้า `log`** (NFR-S02) — log แค่ชื่อ event, ชนิด, ขนาด
