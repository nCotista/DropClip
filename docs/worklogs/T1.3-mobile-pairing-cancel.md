## Scope and observed regressions

Ordinary Doesn't match already rejected correctly. Before the fix, five added widget cases failed: disposing with an unanswered SAS left the decision pending; SAS arriving after disposal, late network failure and late success attempted setState after disposal; repeated confirmation completed the same Future twice. These were reproduced before modifying the UI.

Dispose now rejects an unanswered SAS decision once, clears it and disposes all three text controllers. A late SAS callback returns false without rebuilding; success/error completions check mounted. Settled answers are cleared to prevent duplicate completion. PIN/QR share the same run path. No crypto, wire field, endpoint, trust policy or UI styling is changed.

## Consent boundary

Dismissal **before** a SAS decision rejects the attempt. An explicit Match remains consent: closing the UI after Match does not roll back the underlying protocol result. The late-success test intentionally preserves this existing behavior while proving the disposed dialog is not updated or reopened. This is UI lifecycle cancellation; no new transport-abort or rollback API was introduced.
