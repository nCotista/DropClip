## Verification so far

- Swift probe and its contract checks type-check against the iOS 15 simulator SDK with Xcode 16.2.
- Contract checks run on macOS: passed. They check background session settings, App Group, TLS minimum, file-backed request, invalid inputs, completion handling, and `NWBrowser` construction. `llvm-cov` reports 80.56% line coverage for the Swift probe.
- Android manifest parses with `xmllint`.
- No `dart`, `flutter`, `melos`, Android SDK, Gradle, Kotlin compiler, or `adb` is available in this shell. Android tests have not run.
- An iPhone 16 Pro (iOS 27.0) is paired and has Developer Mode enabled. The missing Apple WWDR G3 intermediate was installed from Apple's certificate authority; `security find-identity -v -p codesigning` now reports one valid Apple Development identity.
- A disposable iOS test host outside the repository built, signed, installed, and launched on the iPhone. `NWBrowser` initially failed with `NoAuth` because the host's `Info.plist` lacked `NSBonjourServices`; with that array and `NSLocalNetworkUsageDescription`, it reached `ready`. This proves browser startup, not discovery of a DropClip peer. ADR-007 records the result.
- At the initial device probe, the repository had no iOS app/Share Extension Xcode target. No 4 GiB upload or peak RAM measurement had run.

## iOS Share Extension follow-up (2026-11-06)

- Added a separate stacked branch `spike/S0.2-ios-share-extension` (`b36f19f`, draft PR #52) with a native host and Share Extension Xcode project, sparse 4 GiB test file, App Group staging, file-backed background upload, `getrusage` peak RSS report, and a TLS 1.3 LAN receiver that verifies byte count and SHA-256. This branch is 390 added lines, stacked on the original S0.2 PR #51 to keep each PR below 400 lines.
- Host and extension compile and install on an iPhone 16 Pro simulator. The simulator registers `group.com.dropclip.shared`; its host created a sparse file with logical size 4,294,967,296 bytes and zero allocated data blocks. Host checks pass with 92.31% line coverage; the receiver's happy path and four error cases pass. The host also requires 16 GiB free before starting the real transfer.
- Physical iPhone build fails for both target IDs: their current provisioning profiles do not authorize `com.apple.security.application-groups = group.com.dropclip.shared`. A disposable group ID fails with the same mismatch under the available signing team. The iPhone 4 GiB transfer and <30 MiB peak RSS criterion remain unmeasured. Both App IDs need profiles with the shared App Group entitlement before device testing.
